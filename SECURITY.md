# Security policy

## Supported versions

Until the first public pre-release is published, no version is formally
supported for security updates. After publication, this file will identify
the supported release line.

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public issue, discussion,
screenshot or log.

Private vulnerability reporting was enabled for the public GitHub repository
by the maintainer on 2026-08-29.

Use GitHub's private vulnerability reporting on the repository **Security**
page. Include the affected version and architecture, a concise description,
reproduction steps, impact and any proposed mitigation. Do not include real
user data or copyrighted material.

If the private reporting button is unavailable, open a public issue containing
only the sentence "I need a private channel for a security report". Do not
include technical details until a private channel has been arranged.

The maintainer will acknowledge the report, assess reproducibility and impact,
coordinate a fix and publish appropriate credit unless the reporter requests
anonymity. No response time is guaranteed before the project has a public
release and an established security team.
